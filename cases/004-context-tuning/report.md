# CASE-004 — Reduce the queue without losing the evidence

This is a constructed tuning experiment, not a captured incident. Four inert JSONL records let me test a narrow question: can a known backup context be marked as expected while preserving alerts for changed users, parents and command lines?

The baseline produces four findings across three events. An exact context profile annotates one finding as context_allowlisted and leaves three for review. All four remain in findings.jsonl, with original evidence references. The change reduces the review queue; it does not erase matches or automatically declare an endpoint safe.

## Fixture and approved context

data/fixtures/context-tuning.jsonl is generated by scripts/build_context_case.py. Host, users, process GUIDs, timestamps and the change reference are synthetic. The commands are strings and are not executed by the fixture generator.

The expected backup context is deliberately narrow: host WS-TUNING-LAB, user LAB\backup.svc, the Windows PowerShell executable, parent taskeng.exe and the exact command powershell.exe -ExecutionPolicy Bypass -File C:\Lab\backup.ps1. SYNTHETIC-CHANGE-004 is part of the fixture specification, not an actual enterprise approval.

Execution-policy bypass can be used legitimately. In this fixture, its purpose is known from the construction. In a real investigation, an analyst would still need evidence of ownership, approval and script content.

## Before and after

| Record / line | Constructed activity | Baseline | With context profile |
| --- | --- | --- | --- |
| 2000 / 1 | Exact backup user, parent and command | WIN-002 needs review | WIN-002 annotated as expected context, evidence retained |
| 2001 / 2 | Same path/command from another user and explorer parent | WIN-002 needs review | Still needs review |
| 2002 / 3 | Backup context but additional EncodedCommand argument | WIN-001 and WIN-002 need review | Both still need review |
| 2003 / 4 | Plain inventory command without bypass/encoding | No match | No match; this is not a general safety verdict |

Queue size changes from four findings to three findings. One event can produce multiple findings; these are not four separate incidents. On this tiny fixture, the exact benign match is the only context-annotated finding.

## Why keep the match?

Broad exclusions such as all PowerShell from a service account would hide useful variation. The profile instead requires the exact host, user, executable, parent and full command. Correlation findings are not eligible for this single-event annotation. The manifest records the profile hash so the classification can be reproduced.

The retained finding includes the context ID, reason and change reference. An analyst can therefore see the original rule match and the explanation used to lower its queue priority. If the context becomes invalid, rerunning without that profile restores the baseline without needing to recollect the source.

## Remaining risk

An attacker who modifies backup.ps1 without changing the command line could still fit the profile. These fields do not verify script content, signature, approval freshness or the parent's legitimacy. Production use would need trusted script/content evidence and maintained approvals; this fixture has none of that operational authority.

The changed-context samples are labeled lookalikes, not real malicious executions. Preserving their review findings demonstrates the profile's boundaries. It does not establish a production false-positive reduction percentage or detection recall.

Record 2002 puts EncodedCommand after -File. Depending on PowerShell argument handling, that text can be passed to the script rather than become a host switch. The substring rule still matches it. This record tests a changed-command boundary; it is not evidence that an encoded payload executed. A parser-aware detector would need to distinguish host arguments from script arguments.

## Decision and reproduction

Close the exact expected-activity finding only within the synthetic experiment's known scenario. Keep the two changed-context events for analyst review, and describe the inventory event as non-matching rather than safe.

scripts/reproduce.ps1 writes both baseline and contextual analysis bundles. Compare their findings_by_status, then inspect records 2000–2003 and rules/context-lab.json. Regression tests change each constrained field independently and ensure the original finding remains visible.
